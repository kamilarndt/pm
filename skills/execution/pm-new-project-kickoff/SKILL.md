# New Project Kickoff — PM Start

## Kiedy użyć
Gdy dostajesz nowy projekt, inicjatywę lub fazę — zanim cokolwiek zaczniesz.

## Workflow

### Step 1: Understand the Project Context
Zbierz baseline:
- **Nazwa/ kod projektu** — jak go nazywamy?
- **Cel biznesowy** — po co to robimy? Jaki problem rozwiązuje?
- **Typ projektu** — nowy produkt / nowa funkcja / redesign / research / eksperyment?
- **Stack / technologia** — co wiemy o tech stacku?
- **Zespół** — kto jest kim? (PM, dev, design, biznes)
- **Stakeholderzy** — kto decyduje? Kto finansuje? Kto blokuje?
- **Timeline** — czy jest deadline? Kamienie milowe?
- **Budżet / zasoby** — ile mamy ludzi, czasu, pieniędzy?

### Step 2: Define Success
- **Cel nadrzędny** — jedna linijka: "Do [kiedy] osiągamy [co] mierzone [jak]"
- **Success metrics** — 3-5 konkretnych, mierzalnych KPI
- **Non-goals** — czego celowo NIE robimy
- **Definition of Done** — kiedy uznamy projekt za zakończony?

### Step 3: Scope & Risks
- **W zakresie** — co robimy
- **Poza zakresem** — czego nie robimy (ważniejsze niż w zakresie)
- **Założenia** — co zakładamy że jest prawdą
- **Ryzyka** — top 5 rzeczy które mogą pójść źle + mitigation

### Step 4: Create Project Charter
```markdown
## Project Charter: [Nazwa]

**Cel**: ...
**Success Metrics**: ...
**Zespół**: ...
**Timeline**: ...
**Ryzyka**: ...

### Zakres
| W zakresie | Poza zakresem |
|-----------|--------------|
| ... | ... |

### Kamienie milowe
| Data | Milestone | Odpowiedzialny |
|------|-----------|---------------|

### Decyzje do podjęcia
| Decyzja | Potrzebne do | Deadline |
|---------|-------------|----------|
```

### Step 5: Save & Share
- Zapisz charter do `/root/vaults/ahe-obsidian/02-Projects/[nazwa]/charter.md`
- Jeśli projekt nie ma katalogu → utwórz
- Zaproponuj follow-up: PRD, roadmapa, OKRy, kickoff meeting
